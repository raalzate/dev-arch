# Implementation Plan: VB.NET Legacy Analyzer

**Branch**: `004-vb-legacy-analyzer` | **Date**: 2026-05-08 (reconstruido 2026-10-07) | **Spec**: [spec.md](./spec.md)

## Summary

Extender `dotnet-analyzer` (Roslyn 4.9.2) para cargar y analizar proyectos VB.NET legacy (.NET Framework 4.x, perfil AmigosPlus). Estrategia: (1) carga por `MSBuildWorkspace` para `.csproj` y `.vbproj` de forma uniforme, con `VbProjectLoader` como fallback `AdhocWorkspace`-equivalente cuando la compilación sale vacía (macOS/Linux o `.vbproj` pre-SDK sin VS Build Tools); (2) filtro de autogenerados a nivel de ruta antes del parseo y a nivel de `SyntaxTree` después de MSBuild; (3) migrar los analizadores estructurales a enumeración por símbolos (`Compilation.GlobalNamespace` / `INamedTypeSymbol`), que es agnóstica de lenguaje, y usar walkers duales C#/VB solo donde la sintaxis es inevitable.

## Architecture

```
ProjectAnalyzer.AnalyzeProjectAsync(path)
  │
  ├── dispatch por extensión
  │     .sln     → MSBuildWorkspace.OpenSolution (proyectos ordenados por FilePath)
  │     .csproj  → MSBuildWorkspace.OpenProject
  │     .vbproj  → VbProjectLoader.WarnIfNonWindows(); MSBuildWorkspace.OpenProject
  │                 └── compilación vacía → VbProjectLoader.LoadAdhoc(path)   (por proyecto)
  │     dir      → .sln si existe; si no, glob *.csproj + *.vbproj
  │     falla total → LoadCompilationsViaAdhoc: .vb (VbProjectLoader) + .cs (LoadCSharpAdhoc)
  │
  ├── VbProjectLoader.StripAutogenerated(compilation)   (uniforme tras MSBuild)
  │
  ├── Pass 1  TypeAnalyzer          — GlobalNamespace → INamedTypeSymbol {Class, Interface, Struct, Module}
  ├── Pass 2  InvocationAnalyzer    — C#: InvocationExpressionSyntax | VB: TypeBlockSyntax/InvocationExpressionSyntax
  ├── Pass 3a DI ctor injection     — C#: ConstructorDeclarationSyntax | VB: ConstructorBlockSyntax.SubNewStatement
  ├── Pass 3b DI implements         — símbolo (AllInterfaces), agnóstico
  ├── Pass 3c DI registrations      — C# only
  ├── Pass x  MessagingDetector     — símbolo (ctor params, fields, properties, AllInterfaces)
  ├── LayerClassifier               — evidencia HTTP / sufijos / tipos base
  ├── Endpoint/Table/Metrics/Secrets/RoslynCodeAnalyzer — C# only (DIFERIDO a 009, no fallan en VB)
  │
  └── Ordering pass: components by id; edges by (from,to,type); endpoints by (method,path);
                     listas por componente dedup + sort ordinal
```

### Equivalencias sintácticas C# ↔ VB usadas

| Concepto | C# | VB |
|---|---|---|
| Declaración de tipo | `TypeDeclarationSyntax` | `TypeBlockSyntax` (Class/Module/Structure/Interface) |
| Referencia de declaración | apunta al `ClassDeclarationSyntax` completo | apunta a `ClassStatementSyntax` → subir al `*BlockSyntax` padre para LOC |
| Constructor | `ConstructorDeclarationSyntax.ParameterList` | `ConstructorBlockSyntax.SubNewStatement.ParameterList` |
| Invocación | `CSharp.Syntax.InvocationExpressionSyntax` | `VisualBasic.Syntax.InvocationExpressionSyntax` → mismo `IMethodSymbol` vía `SemanticModel` |
| Comentario de línea | `//` | `'` y `REM` |
| Tipos sintéticos | — | `My.*` con `DeclaringSyntaxReferences` vacío → se omiten |

## Complexity Tracking

| Desviación | Justificación |
|---|---|
| Walkers duales en `InvocationAnalyzer` y DI ctor | Las invocaciones y constructores no se pueden enumerar solo por símbolos sin perder la ubicación del llamador; la lógica de símbolo se comparte |
| Registros DI solo C# | El perfil VB objetivo no usa `IServiceCollection`; portar sería superficie sin uso |
| Tests de corpus dependientes de un corpus externo | Único medio de validar SC-002/003/004 sobre código real; aislados con `Category=Corpus` |

## Implementation Order (TDD)

1. Setup: NuGet VB + RollForward; fixture VB mínimo; usage del CLI (T001–T004)
2. Foundational: filtro de autogenerados → loader VB → dispatch/ordering en `ProjectAnalyzer` (T005–T012)
3. Analizadores agnósticos: Type → Invocation → DI → Messaging (T013–T016)
4. Corrección sobre corpus real: LOC VB + LayerClassifier (da3f0cc → T046/T047 parciales)
5. Cierre: detección `.vbproj` en Java, limpieza de artefactos, reconstrucción de specs, verificación (T048–T053)
