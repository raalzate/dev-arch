# Installing dev-arch

dev-arch (Next.js web + Static Inference engine + .NET analyzer) installs in two ways:

- **Local installation** — JDK, Maven, .NET and Node on your machine; build from source with `make build`.
- **Docker installation** — only Docker 24+ with the Compose v2 plugin; one all-in-one container.

Before either route, run the doctor: it lists every requirement with `OK`, `WARN` or `FAIL`, the detected and the
required version, and the install command for your operating system.

```bash
cd apps/dev-arch
npm run doctor                 # same as: npx dev-arch doctor   (Node 20+ is the only prerequisite)
npm run doctor -- --fix        # also show the install commands (they are never executed)
npm run doctor -- --json       # machine-readable report (CI, health checks)
npm run doctor -- --mode docker   # only the checks of the Docker route
```

Exit code: `0` without `FAIL`, `1` with at least one `FAIL`, `64` on a usage error. `WARN` never fails the command.

Status rules: a missing or too old build/runtime dependency (JDK, Maven, .NET SDK, .NET 8 runtime, Node/npm) and a
broken `ENGINE_JAR_PATH` are `FAIL`. An engine archive or `dotnet-analyzer` that is not built yet or was built at
another version, Visual Studio Build Tools on Windows, Docker in local mode, a missing AI key, a port used by another
process and low memory/disk are `WARN`. A newer .NET SDK (for example SDK 10) is fine as long as a **.NET 8 runtime**
is installed: the analyzer targets .NET 8.

## Local installation

1. Run `npm run doctor -- --fix` (or `make check-env`, which runs the doctor in local mode and fails on `FAIL`) and
   install what it reports.
2. Build everything: `make build` (engine JAR + .NET analyzer staged into `web/engine-dist`, npm workspace, web
   build). `make build-engine` builds only the engine.
3. Start the web: `make dev` (http://localhost:9002) or, after `make build`, `npm run start -w web -- -p 9002`.
4. Check the running web: `curl -s http://localhost:9002/api/health` — `200` with the state of the engine archive,
   the .NET analyzer and the engine process, `503` when a runtime check fails.
5. Optional: `java -jar web/engine-dist/engine.jar --doctor` prints the engine version, the output schema version and
   whether it locates `dotnet-analyzer`.

Environment variables: `GEMINI_API_KEY` or `GOOGLE_GENAI_API_KEY` (AI features; static analysis works without
them), `LLM_MODEL`, `ENGINE_JAR_PATH` (engine archive, relative to `web/`), `DOTNET_ANALYZER_PATH`, `JAVA_HOME`,
`DOTNET_ROOT` (Homebrew .NET installs), `DEVARCH_API_TOKEN` (protects the API when the web listens on every interface).

`make doctor` is still a reserved placeholder (feature 006); use `make check-env` or `npm run doctor`.

## Docker installation

Requirements: Docker 24+ and Compose v2 (`docker compose version`). Check them with `npm run doctor -- --mode docker`
(needs Node) or simply `docker compose version`.

```bash
cd apps/dev-arch
docker compose -f docker/compose.yaml up -d          # build (first time) and start the all-in-one web
docker compose -f docker/compose.yaml ps             # STATUS shows (healthy) once GET /api/health answers 200
open http://localhost:9002
docker compose -f docker/compose.yaml down           # stop (the analyses stay in the dev-arch-data volume)
```

- **Image**: `docker/Dockerfile` builds the engine (Maven, JDK 17), the .NET analyzer (.NET 8 SDK, for the target
  architecture) and the web (Node 20, standalone output) in separate stages; the final image only has the JRE 17,
  the .NET 8 runtime and Node 20, runs as a non-root user and declares a health check on `/api/health`.
  Build it alone with `docker build -f docker/Dockerfile -t dev-arch .` (from `apps/dev-arch`).
- **Variables**: put them in `docker/.env` (read by Compose) or export them: `GEMINI_API_KEY`,
  `GOOGLE_GENAI_API_KEY`, `LLM_MODEL`, `DEVARCH_API_TOKEN`, `JAVA_TOOL_OPTIONS` (default `-Xmx2g`),
  `DEV_ARCH_MEM_LIMIT` (default `4g`), `DEV_ARCH_PORT` (default `9002`), `DEV_ARCH_IMAGE` (default `dev-arch:local`).
- **Data**: analyses and uploads live in the named volume `dev-arch-data` (`/data` in the container); expired
  analyses are removed after `ARCHVIEW_JOB_TTL_HOURS` (default 24).
- **Health**: the container health check calls `GET /api/health`; inside the container
  `node /opt/dev-arch/scripts/doctor/cli.mjs --only jdk,dotnet-runtime,engine-jar,dotnet-analyzer` checks the engine.
- **Development profile**: `docker compose -f docker/compose.yaml --profile dev up web-dev` mounts the sources with
  hot reload on http://localhost:9003. Build the engine on the host first (`make build-engine`); the container copies
  `engine/target/java-dependency-extractor.jar` next to its own Linux `dotnet-analyzer` at start.
- **Published image**: release tags `dev-arch-vX.Y.Z` publish `ghcr.io/<owner>/dev-arch:X.Y.Z` and `:latest`; set
  `DEV_ARCH_IMAGE` to use it instead of building.

Limitation: the image has the .NET runtime but not the .NET SDK, so the analyzer cannot load MSBuild workspaces and
falls back to its ad-hoc workspace (reduced semantic accuracy for .NET projects compared with a local installation
that has the SDK). Java analysis is identical.

## Troubleshooting

| Symptom | Check |
|---|---|
| `make build` stops at `[prereqs]` | `npm run doctor -- --fix` |
| The web answers `ENGINE_NOT_BUILT` | `make build`, or fix `ENGINE_JAR_PATH` (doctor check `engine.jar`) |
| .NET projects are analyzed as Java | doctor checks `.NET runtime` and `dotnet-analyzer` |
| Container stays `unhealthy` | `docker compose -f docker/compose.yaml logs web` and `curl -s localhost:9002/api/health` |
