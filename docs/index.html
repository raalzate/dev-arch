=misma entrada, misma salida

La tesis

Un modelo estima; dev-arch mide.

Un modelo de lenguaje es excelente escribiendo y transformando código, pero cuando se le pregunta cómo está un sistema grande responde con una estimación: lee una parte, completa el resto por probabilidad y puede alucinar dependencias, capas o tablas. Una decisión de arquitectura apoyada en una descripción inventada es peor que ninguna.

dev-arch no genera: mide. Recorre el árbol sintáctico completo (Spoon para Java, Roslyn para C# y VB.NET) y construye el grafo real de dependencias, las capas, las tablas y procedimientos que toca cada componente, los contratos REST, los secretos expuestos y los problemas de código. Sobre ese grafo aplica una inferencia con pesos y umbrales explícitos para proponer microservicios con su viabilidad y su justificación.

El agente (Claude Code u otro cliente MCP) decide cómo refactorizar; dev-arch le dice qué hay y si quedó mejor. Como la salida es reproducible byte a byte, dos análisis se comparan: eso convierte el motor en un guardrail objetivo y hace posible la modernización continua.

3comandos

Quick start

Compila, arranca y analiza.

Local (JDK 17, Maven, .NET SDK 8, Node 20+) o Docker. npm run doctor lista cada requisito con su comando de instalación.

# local
git clone https://github.com/raalzate/dev-arch.git && cd dev-arch
make build                 # motor Java + analizador .NET + web
make dev                   # http://localhost:9002

# o con Docker
docker compose -f docker/compose.yaml up -d

# un análisis desde la línea de comandos
java -jar engine/target/java-dependency-extractor.jar ./mi-proyecto salida.json --language=auto

Abre la web, sube el .zip del proyecto y recorre los cinco pasos. Detalle y solución de problemas en INSTALL.md.

5preguntas, un análisis

El producto

Cinco pasos sobre el mismo análisis determinista.

1 · Resumen

¿En qué estado está el sistema legacy?

Componentes, líneas, dependencias, endpoints, propuestas y la salud del código: críticos, errores, advertencias, secretos, tablas y dependencias externas. Avisos del análisis y de fidelidad.

2 · Mapa del sistema

¿Dónde está el acoplamiento real?

Grafo de dependencias agrupado por capa o por propuesta, filtros por tipo de dependencia, resaltado por severidad y detalle de cada componente en un panel lateral.

3 · Propuestas

¿Qué se puede extraer y con qué viabilidad?

Microservicios candidatos con métricas, señales y justificación; parámetros de inferencia ajustables y re-inferencia sin volver a analizar.

4 · Hallazgos

¿Qué riesgos y contratos hay que atender?

Problemas de código por severidad o patrón, secretos, contratos REST, puntos de entrada legacy e inventario tecnológico.

5 · Plan

¿En qué orden modernizar?

Etapas por viabilidad, librerías de soporte y exportación a Markdown/JSON para la propuesta.

⌕todo el análisis

Proyectos grandes

Mil componentes sin perder el hilo.

Buscador léxico en la barra superior sobre componentes, propuestas, problemas, tablas y procedimientos, puntos de entrada y advertencias, con navegación directa al paso y al componente. Mapa con zoom fluido, detalle en un panel lateral no modal con historial, y listas paginadas con la selección siempre visible.

Método

Modernización continua.

Ejecutado en cada cambio —en la CI o por el agente tras cada refactorización— el análisis se convierte en un guardrail: no deja que aumenten los hallazgos críticos, que crezca el acoplamiento, que baje la cohesión ni que una propuesta pierda viabilidad. El historial de la web compara dos análisis lado a lado.

Grafo determinista

Componentes, capas, datos, contratos, problemas.

2 · Decidir

Propuestas y plan

Viabilidad explicada, parámetros ajustables.

3 · Refactorizar

Agente de IA

Cambios pequeños, sobre hechos.

4 · Comparar

Reanalizar

VB.NET Framework 4.8

Perfil legacy

Lo que un monolito de escritorio VB.NET necesita.

Soporte para la plataforma típica de escritorio .NET Framework: formularios, controladores, adaptadores ADO.NET con procedimientos almacenados, Enterprise Library, servicios SOAP/WCF, proyectos anidados. Funciona también sin Windows (fallback Adhoc con fidelidad reducida, mejorable con ensamblados de referencia).

Datos

Procedimientos almacenados

sp:<nombre> por componente, catálogo opcional sp → tablas, peso en la inferencia.

Identidad

Capas y puntos de entrada

Namespace raíz, Presentación/Reportes/Batch, Sub Main, seis reglas de deuda legacy.

Integraciones

SOAP, WCF, REST y EOL

Referencias de servicio, URL por configuración, proyectos ausentes y dependencias fin de vida.

Inferencia

Preset legacy-desktop

Cortes verticales por entidad, nombres por dominio, librerías de soporte e índice de deuda.

Análisis

Reglas oficiales .NET, código muerto, duplicación, índice de mantenibilidad, importación SARIF.

Fidelidad

VB-LEGACY.md · medidas sobre el corpus de referencia

{}sin configuración, 1.2.0 exacto

Configuración

Cada peso y umbral, explícito.

La inferencia es un objeto JSON parcial: agrupación, evidencia, consolidación, viabilidad, nombres, acceso a datos, deuda, integraciones y análisis extendido. Sin configuración el motor es byte a byte la versión anterior; un preset versionado (legacy-desktop) se aplica entre los valores por defecto y los tuyos.

{
  "detection":  { "maxDepth": 3 },
  "analysis":   { "extended": "on", "referenceAssemblies": "~/.nuget/.../v4.8" },
  "inference":  { "preset": "auto" },
  "viability":  { "thresholds": { "high": 0.7, "medium": 0.5 } }
}

Referencia completa: engine/CONFIGURATION.md.

—lo que no hace

Límites declarados

Mide; no decide por ti.

fidelidad reducida Sin Windows, los proyectos .NET Framework se compilan en modo Adhoc: los tipos del framework no se resuelven salvo que indiques una carpeta de ensamblados de referencia; terceros (DevExpress, Enterprise Library) requieren sus binarios.

viabilidad honesta Un monolito en capas de un solo dominio seguirá dando propuestas de viabilidad baja: el preset mejora los cortes y los nombres, no inventa cohesión.

no es un refactorizador dev-arch no cambia código; entrega hechos y comparaciones para que lo haga una persona o un agente.

determinista por contrato Toda salida se valida contra el esquema 1.0.0 y se compara byte a byte en las pruebas de regresión.
